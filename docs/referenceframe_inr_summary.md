# Reference-Frame 引导的 INR 流场压缩 —— 项目梳理

> 面向读者的总结。目标：把"做了什么、怎么做的、结果如何、下一步"讲清楚。
> 所有数字都标了出处（哪个脚本、哪个日志文件）。训练是确定性的（固定随机种子 + 锁 CUDA 确定性），
> 同样设置重跑会得到**一模一样**的数字，可自行复算。脚本与日志都在 `experiments/referenceframe_inr/`。

---

## 1. 这个项目想干什么

时变流场（随时间变化的二维向量场）数据量大，想用神经网络**压缩**它。

- **标准做法（baseline）**：训练一个神经网络 INR，输入坐标 `(x, y, t)`、输出该点的流场向量 `(u, v)`，
  让它拟合整个场。训练好的网络权重就是"压缩后的数据"，要用时把任意坐标喂进去就能重建流场。
  压缩比 = 原始数据大小 ÷ 网络权重大小；重建质量用 PSNR 衡量。

- **想验证的新想法**：先把场按空间**切成几块**，每一块找一个"**观察者变换**"，把这块变换到一个
  跟着它运动的参考系里（让流场看起来更简单、更接近静止），然后**每块用一个小 INR** 去拟合变换后的场。
  问题：这样是否比 baseline 更好——**在同样的参数量下拿到更高的 PSNR**？

一句话：**"切块 + 每块换个运动参考系 + 每块一个小网络"，能不能打败"一个大网络直接拟合整场"。**

---

## 2. 几个名词（大白话）

| 名词 | 意思 |
|---|---|
| **INR**（隐式神经表示） | 一个神经网络，输入坐标输出场值。这里用的是固定结构：Fourier 特征 + ReLU 多层网络（`ff_inr.py`）。 |
| **baseline** | **唯一的对照**：一个 INR 直接拟合整个场，**没有分区、没有 observer**。全项目就这一个 baseline。 |
| **observer 变换** | 给一块流场找一个"跟着它平移+旋转"的参考系。打个比方：相机跟着旋转的物体一起转，画面里它就几乎不动了。数学上每块用 3 个随时间变化的参数（两个平移速度 + 一个转速）描述这个参考系。变换后的场叫 "observed field"，理论上更简单、更好拟合。 |
| **分区** | 把整个场按空间切成 N 块，每块单独用一个小 INR 处理。 |
| **PSNR** | 重建质量指标，单位分贝(dB)，**越高越好**。43dB 比 41dB 好。 |
| **参数预算** | 网络权重总量。为公平，baseline 和新方法用**一样多**的参数（这里固定 3.94M）。参数越多压缩比越低。 |
| **epochs** | 训练轮数。越多训练越充分，但越慢。 |

---

## 3. 测了哪些数据

只测了 **3 个场**：

| 场 | 是什么 | 尺寸（帧×高×宽） | 特点 |
|---|---|---|---|
| **rfc** | 解析构造的旋转场（`rotation_four_center`） | 64×64×64 | 整体可被一个旋转参考系解释，最"配合" observer |
| **cylinder2d** | 圆柱绕流，尾流涡街脱落 | 128×80×320 | **本征非定常**：涡街脱落没法用刚体参考系消掉 |
| **boussinesq** | 热对流羽流上升 | 128×225×75 | 有较强的整体运动结构 |

---

## 4. 一个必须先说清的前提：训练轮数

项目中途有一个关键约束变化：**要求任何实验 ≤ 1000 epochs**。

这件事的后果很重要：baseline 是**最大的单个网络**，1000 步没把它训够（欠训练）。同一个 baseline：

| baseline（同一个方法） | cylinder2d | boussinesq |
|---|---|---|
| 训 2500 步（早期，现已**作废**） | 49.17 | 48.93 |
| 训 1000 步（现在的口径） | **43.42** | **41.02** |

**同一个 baseline，只是训练步数不同，数字差 6~8 dB。** 本文档**只用 1000 步这一套**；早期 2500 步的
所有实验（包括基于它的对比）一律作废，仅在附录 B 留档。

> ⚠️ 记住这个欠训练问题，它是下面结论的最大不确定来源（见第 7 节）。

## 5. 做了什么 + 结果（全部 @1000 epochs，固定 3.94M 参数，脚本 `rfo_final8.py`）

### 5.1 核心结果表

| 方法 | cylinder2d | boussinesq | 出处 |
|---|---|---|---|
| **baseline**：一个 INR 拟合整场（无 observer、无分区） | 43.42 | 41.02 | `logs/final8_cyl.log` / `final8_g0.5.log` |
| **纯分区**：切成小块，每块一个小 INR（**无 observer**） | **46.11** | 42.98 | `final8_cyl.log` / `final8_ablation.log` |
| **分区 + observer**：每块先做参考系变换再拟合 | 44.05 | **45.37** | `final8_cyl.log` / `final8_g0.5.log` |

（cylinder 切 5 块，boussinesq 切 3 块——这个块数是早期各场表现最好的值。）

### 5.2 从这张表能读出三件事

**① 分区本身有用（两个场都是）。** 纯分区 vs baseline：
- cylinder：46.11 − 43.42 = **+2.69**
- boussinesq：42.98 − 41.02 = **+1.96**

把一个难训的大网络拆成几个好训的小网络，两个场都涨。**但注意：这个"涨"可能有一部分是 baseline 没训够
造成的假象**（第 7 节详述）。这也不是本方法的独有卖点——任何 INR 都能切块。

**② observer 变换是"看场下菜"，不是普遍有用。** 把上面两行相减（分区+observer 减 纯分区 = observer 单独的作用）：
- cylinder：44.05 − 46.11 = **−2.06（有害！）**
- boussinesq：45.37 − 42.98 = **+2.39（有益）**

在 cylinder 上，加了 observer 反而**更差**，纯分区(46.11)才是全场最好的配置。在 boussinesq 上，observer 帮了 +2.39。
**这个对比是干净的**：两边网络一样大、都训 1000 步，欠训练程度相同，唯一差别就是 observer 有没有，所以
"observer 依场而定"这个结论比较**硬**。

**③ 整体方法（分区+observer）vs baseline：** cylinder +0.63、boussinesq +4.35。两个场都赢 baseline，
但 cylinder 赢主要靠分区、observer 在拖后腿。

### 5.3 "自适应参数分配"试过了，没用

想法：既然切成几块，能不能把参数**不均分**——难的块多给、简单的块少给？在 boussinesq（3 块）上试了三种分法：

| 参数怎么分 | boussinesq PSNR | 出处 |
|---|---|---|
| **均分**（每块一样大） | **45.37** | `final8_g0.5.log` |
| 按像素数分（大块多给） | 43.61 | 同上 |
| 按难度分（残差大的块多给） | 44.01 | 同上 |
| 按 难度×像素 分 | 44.09 | 同上 |

**结论：均分最好，任何不均分都更差（差 1.3~1.8 dB）。** 猜测原因：observer 变换后每块都变得比较好拟合、
需要的容量差不多，从任何一块抽参数都是净损失。这个方向（自适应分配）到此为止。

---

## 6. 到目前为止的结论

**比较确定的（有干净对比支撑）：**
1. **observer 变换不是普遍有用，而是看场**：boussinesq 上有益（+2.39），cylinder 上有害（−2.06）。
   涡街这种本征非定常的场，刚体参考系解释不了，硬做变换反而伤害。
2. **自适应参数分配没用**，均分最好（仅 boussinesq 验证）。
3. **切块（分区）本身能涨 PSNR**，但见下面的不确定性。

**还只是猜测（证据不足，别当结论）：**
4. "场越能被刚体参考系解释（`decomposition_benefit` 越高），observer 越有用"——boussinesq(0.43) 有益、
   cylinder(0.11) 有害，看起来对上了，但**只有两个场，是巧合还是规律说不准**。`decomposition_benefit` 是
   分区代码里本来就有的一个诊断数字，不是新东西。

---

## 7. 最大的坑 / 没解决的问题

**baseline 欠训练，导致"分区到底真好，还是只是 baseline 没训够"分不清。**

baseline 是最大的单网络，1000 步没训够。分区方法用的是小网络，1000 步相对训得更充分。所以"分区赢 baseline"
里，有多少是"分区真的好"、有多少是"baseline 被 1000 步坑了"，**目前无法区分**。

- 对 **observer 依场而定**这个结论**没影响**——那个对比两边网络一样大、一样欠训练，抵消了。
- 对 **分区 vs baseline**这个对比**有影响**——需要下一步专门排查。

---

## 8. 可能的下一步方向

按重要性排：

1. **【最该做】公平性检验：让 baseline 也训够。** 办法：在 1000 步内用更小的 batch（增加梯度更新次数），
   或两边都放开训练充分。看"分区赢 baseline"是否还在。这直接回答第 7 节的坑——不解决它，"分区有用"就站不稳。

2. **查 observer 为什么在 cylinder 有害。** 怀疑是参考系变换把每块的坐标范围旋转+平移**放大**了，
   重新归一化后丢了高频细节。可以检查变换前后的坐标范围、或给变换后的场单独调网络的频率参数，看能否止损。

3. **多测几个场。** 现在就 3 个场，"observer 依场而定""benefit 能否预测"都需要更多场（rfc、beads、duffing 等）
   才能坐实，否则都是两三个点的巧合。

4. **如果确认 observer 依场而定**：把方法做成"**按场自动决定要不要 observer**"——高 benefit 的场用 observer，
   低 benefit 的场就纯分区。这样每个场都能取到各自最优（cylinder 用纯分区 46.11、boussinesq 用 observer 45.37），
   都赢 baseline。这是目前看最诚实、能自圆其说的方法定位。

## 附录 C. 怎么自己验证任何一个数字

```bash
cd experiments/referenceframe_inr
# 例：重算 boussinesq 的 baseline / 均分 / 自适应分配（会打印 PSNR，和 logs/ 里一致）
python rfo_final8.py --fields boussinesq --weights uniform,pixels,residual,respix
# 例：boussinesq 去掉 observer（纯分区）的对照
python rfo_final8.py --fields boussinesq --weights uniform --no-observer --skip-baseline
# 例：cylinder 三点（baseline / 分区+observer / 纯分区）
python rfo_final8.py --fields cylinder2d --weights uniform
python rfo_final8.py --fields cylinder2d --weights uniform --no-observer --skip-baseline
```

因为固定了随机种子并锁了 CUDA 确定性，重跑得到的 PSNR 会和 `logs/` 里记录的**逐位一致**。
